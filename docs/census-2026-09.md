## Detector quality: the v0 rule over-flagged, and content inspection fixed it

The v0 critical rule flagged any hook containing `node -e`. Against the three artifacts it produced **three false positives in three cases**: two install banners and one build step (`npm run build`). That is a 0% precision on the critical tier, and it is the failure mode that makes security tooling ignorable.

v0.1 replaces the pattern with evidence of fetch (`curl`, `wget`, a URL), a shell (`sh -c`, `| sh`), a process spawn (`child_process`, `execSync`, `spawn`) or decode-and-exec (`eval`, `base64 -d`), and adds a second layer: when a hook runs a local script (`node scripts/install.js`), that file is fetched from the published package and statically scanned. The second layer is what surfaced the pattern below — the hook alone is opaque.

## Notable pattern: install hooks that download and execute a binary (13 servers)

A family of packages publishes a `postinstall` of `node scripts/install.js`. Inspecting the published script (read-only, from the package registry) shows it:

1. resolves a platform-specific archive from a GitHub release;
2. downloads it over HTTPS;
3. downloads a SHA-256 sidecar from the **same origin** and verifies the archive;
4. extracts it (`tar` / `unzip` / PowerShell `Expand-Archive`) and installs the binary.

Two properties are worth recording, and neither is a vulnerability claim:

- The checksum protects against transport corruption, **not** against a compromised release origin, because the expected hash is fetched from the same base URL as the artifact.
- The base URL and version are overridable through environment variables (`LABBY_REPO`, `LABBY_VERSION`). A redirected download is then validated against a checksum fetched from the same redirected location, so the verification adds no protection in that path.

For an MCP client, this means "install the server" silently becomes "download and run a platform binary". That is a trust decision users should be able to see, and no npm metadata field surfaces it today.

## What this census does not cover

- PyPI / OCI / MCPB packages (52 servers): not audited, not clean.
- Remote endpoints: never contacted, by design.
- Runtime behaviour: static findings are not proof of exploitability.
